# Macmini Control Surface

Base URL: http://macmini:5555  (also reachable on LAN / tailnet by hostname or IP)

Local home-server landing page + agent API for Kix's "quick-arr-stack".
No authentication. Exposed only over the LAN / tailnet — treat it as private.

## Host context

- Machine: macmini (Apple M2 Pro, 32 GB unified memory, macOS)
- Timezone: Asia/Manila (UTC+8). All dates are YYYY-MM-DD in Manila time; omitting a date defaults to today (Manila).
- Services on the landing page: Coins.ph Agent (:7777), Hermes Agent (:9119), Opencode (:4096).
- The page at / is a service grid + a Daily Brief markdown canvas (one entry per day, autosaved).

## Views (tabs)

The page has tabs sharing one header + live sys-monitor cards (CPU / Memory /
Power, 1s tick with 1h graphs). Hash routes: `#/brief`, `#/` (Stack, default),
`#/files`, `#/shell`, `#/kanban`.

- **Brief** — Daily Brief markdown canvas (one entry per day, autosaved) + weekly schedule side panel.
- **Stack** — service grid with the `/`-focused filter scanner.
- **Files** — host filesystem browser rooted at `~`: browse folders, create files/folders, upload/download, rename, delete, click any entry for full details, and open any text file in an inline editor (syntax highlighting, save in place, download).
- **Shell** — interactive host tty rooted in `~` (see Web shell below).
- **Kanban** — a small Trello-style board: lanes as columns, cards with title + owner + a markdown body, drag and drop, inline owner edit. Click a card to open its detail modal (edit title / owner / lane, rendered markdown body with a Write + live Preview editor, clickable checklists); `#/kanban/card-<id>` deep-links a card, `#/kanban/card-<id>/edit` opens it in the editor. Polls every 3 s, so cards agents write through `/api/kanban` appear on their own (see Kanban board below).

## API

### Daily Brief — markdown notes, one entry per day

Stored in SQLite at /Users/kixpanganiban/quick-arr-stack/arr-dashboard/data/briefs.db (host mount — survives container rebuilds).

Markdown previews (Daily Brief and weekly schedule) render through a sanitizer: script/style/iframe/object/embed/link/meta/base/form elements, `on*=` handlers, and `javascript:`/`data:`/`vbscript:` URLs are stripped before insert; the stored markdown is unchanged.

| Method | Path | Behavior |
|--------|------|----------|
| GET    | /api/brief?date=YYYY-MM-DD | Fetch a day's entry. Returns {"date", "content"} — content is "" when no entry exists yet. |
| GET    | /api/brief/list?limit=N | All entries, newest first. Default limit 30, max 365. |
| PUT    | /api/brief | Create or replace a day's entry. JSON body: {"date"?: "YYYY-MM-DD", "content": "markdown string"}. |
| POST   | /api/brief | Same as PUT. |
| DELETE | /api/brief?date=YYYY-MM-DD | Delete a day's entry. 404 if it doesn't exist. |

PUT/POST examples (post today's brief):

    curl -X PUT http://macmini:5555/api/brief \
      -H 'Content-Type: application/json' \
      -d '{"content":"# Daily Brief\n\n- shipped the landing page brief feature"}'

Explicit date (for any day):

    curl -X PUT http://macmini:5555/api/brief \
      -H 'Content-Type: application/json' \
      -d '{"date":"2026-08-14","content":"..."}'

Read today's entry:

    curl http://macmini:5555/api/brief

The weekly schedule (`GET|PUT|POST|DELETE /api/schedule`, `GET /api/schedule/list`) uses the same `YYYY-MM-DD` week form; `week` coerces to that week's Monday, and a well-formed but impossible date such as `2026-02-30` returns 400 rather than 500.

### Kanban board — lanes + cards, agent-drivable

Stored in the same SQLite database (tables `kanban_lane`, `kanban_card`), so cards
survive restarts. No auth, same as everything else here. Default lanes on first
start: Backlog, To Do, In Progress, Done. Lanes are data: add, rename, reorder,
or delete them through the API.

Card: `{"id", "title", "owner" (string or null), "status" (lane name), "lane_id",
"position" (0-based within the lane, 0 = top), "created_at", "updated_at",
"archived_at" (null, or when it was archived), "body" (markdown string, "" when
empty), "has_body" (bool), "body_preview" (first prose line of the body, markers
stripped, max 140 chars), "body_tasks" (`{"done", "total"}` checklist counts, or
null)}`.

Body: free-form **markdown** (GFM: headings, lists, `- [ ]` / `- [x]` task
items, fenced code, links, tables), up to 200,000 characters. It is stored
verbatim (CRLF normalised to LF); `null` or whitespace-only clears it to "".
The board UI renders it sanitized (marked + DOMPurify), so HTML in a body is
never executed. **Listings (`GET /api/kanban`, `/api/kanban/cards`,
`/api/kanban/archived`) omit `body`** and return only the summary fields, to
keep the 3 s poll light; pass `?include_body=1` for full bodies, or read one
card with `GET /api/kanban/cards/:id` (always full). POST/PATCH responses return
the full card, body included.
Lane: `{"id", "name", "position", "card_count" (visible cards), "archived_count",
"created_at", "updated_at"}`.

Archiving: archived cards are hidden from the board and from every card listing
by default, but they are kept (not deleted) and stay readable by id. Positions
stay contiguous among the visible cards of each lane; an archived card's
`position` is just where it sat when archived. The board's **Archive Done**
button (Done column header, two-click confirm) calls `POST /api/kanban/archive-done`.

Wherever a lane is referenced (`status` in a card body, `?status=`, the `:lane`
path segment, `?target=`) you can pass the lane name, **case-insensitive**
("in progress" = "In Progress"), or its numeric id. Errors are JSON
`{"error": "..."}`: 400 bad input (unknown lane, empty title, unknown field,
bad position), 404 missing card/lane, 409 conflict (duplicate lane name,
deleting a non-empty lane).

| Method | Path | Behavior |
|--------|------|----------|
| GET    | /api/kanban?status=&owner=&include_archived=&include_body= | `{"lanes": [...], "cards": [...]}`. All lanes always; non-archived cards ordered by lane then position, optionally filtered by `status` (lane) and/or `owner` (case-insensitive exact; `owner=` empty = unowned). `include_archived=1` also returns archived cards (after the visible ones, `archived_at` set). Cards carry `has_body` / `body_preview` / `body_tasks` but no `body` unless `include_body=1`. |
| GET    | /api/kanban/cards?status=&owner=&include_archived=&include_body= | Just the cards array (same filters). |
| GET    | /api/kanban/archived?status=&owner=&include_body= | Archived cards only, most recently archived first. |
| POST   | /api/kanban/archive-done | Archive every non-archived card in the lane named "Done" (case-insensitive) → `{"archived": N, "ids": [...], "lane", "archived_at"}`. No body needed. 404 if there is no Done lane. |
| POST   | /api/kanban/cards | JSON `{"title", "owner"?, "status"?, "position"?, "body"?}` → 201 + card. `status` defaults to the first lane; `position` defaults to the bottom. Title max 500 chars, owner max 100, body (markdown) max 200,000. |
| GET    | /api/kanban/cards/:id | One card, **with its full markdown `body`** (archived cards too). 404 if missing. |
| PATCH  | /api/kanban/cards/:id | Any of `{"title", "owner", "body", "status", "position", "archived"}`. `body` replaces the whole markdown body (read it first to append; `null` clears). Changing `status` without `position` appends to the bottom of the new lane; `position` alone reorders within the lane. `"owner": null` (or "") clears it. `"archived": true` archives one card; `"archived": false` restores it to the bottom of its lane (or to `status` / `position` if given). `archived` must be a JSON boolean. |
| DELETE | /api/kanban/cards/:id | Delete → `{"deleted": id, "card": {...}}`. |
| GET    | /api/kanban/lanes | Lanes in board order, with `card_count`. |
| POST   | /api/kanban/lanes | JSON `{"name", "position"?}` → 201 + lane. Names are unique (case-insensitive), max 60 chars, not all digits. |
| PATCH  | /api/kanban/lanes/:lane | `{"name"?, "position"?}` — rename and/or move the column. Cards follow a rename automatically. |
| DELETE | /api/kanban/lanes/:lane | Refused with 409 if the lane has cards (visible or archived), unless `?target=<lane>` (cards move to that lane; visible ones go to the bottom) or `?force=1` (cards are deleted too). |

Examples:

    # whole board
    curl http://macmini:5555/api/kanban

    # add a card (lands in Backlog)
    curl -X POST http://macmini:5555/api/kanban/cards \
      -H 'Content-Type: application/json' \
      -d '{"title":"Renew the domain","owner":"hermes"}'

    # add straight into a lane
    curl -X POST http://macmini:5555/api/kanban/cards \
      -H 'Content-Type: application/json' \
      -d '{"title":"Fix backup cron","status":"to do"}'

    # move card 7 to In Progress, at the top
    curl -X PATCH http://macmini:5555/api/kanban/cards/7 \
      -H 'Content-Type: application/json' \
      -d '{"status":"in progress","position":0}'

    # edit title / owner
    curl -X PATCH http://macmini:5555/api/kanban/cards/7 \
      -H 'Content-Type: application/json' \
      -d '{"title":"Fix the backup cron job","owner":"kix"}'

    # my cards still in flight
    curl 'http://macmini:5555/api/kanban?owner=hermes&status=in%20progress'

    # delete a card
    curl -X DELETE http://macmini:5555/api/kanban/cards/7

    # card with a markdown body (use the handoff template below)
    curl -X POST http://macmini:5555/api/kanban/cards \
      -H 'Content-Type: application/json' \
      -d '{"title":"Migrate backups to restic","owner":"hermes","status":"in progress","body":"## Goal\nMove nightly backups to restic.\n\n## Next steps\n- [ ] write the cron\n- [ ] test a restore"}'

    # read one card with its full body; replace the body
    curl http://macmini:5555/api/kanban/cards/7
    curl -X PATCH http://macmini:5555/api/kanban/cards/7 \
      -H 'Content-Type: application/json' -d '{"body":"## Goal\n..."}'

    # whole board including every body
    curl 'http://macmini:5555/api/kanban?include_body=1'

    # archive one card / restore it
    curl -X PATCH http://macmini:5555/api/kanban/cards/7 \
      -H 'Content-Type: application/json' -d '{"archived":true}'
    curl -X PATCH http://macmini:5555/api/kanban/cards/7 \
      -H 'Content-Type: application/json' -d '{"archived":false}'

    # archive everything in Done (same as the board's Archive Done button)
    curl -X POST http://macmini:5555/api/kanban/archive-done

    # see archived cards
    curl http://macmini:5555/api/kanban/archived
    curl 'http://macmini:5555/api/kanban?include_archived=1'

    # lanes: add "Review" as the 4th column, rename it, delete it (moving cards to Done)
    curl -X POST http://macmini:5555/api/kanban/lanes \
      -H 'Content-Type: application/json' -d '{"name":"Review","position":3}'
    curl -X PATCH http://macmini:5555/api/kanban/lanes/review \
      -H 'Content-Type: application/json' -d '{"name":"QA"}'
    curl -X DELETE 'http://macmini:5555/api/kanban/lanes/qa?target=done'

#### Card body handoff template (agents: use this)

When an agent picks up, works on, or hands off a card, keep the card's `body`
in this shape so the next agent (or Kix) can resume without asking. Set
`owner` to your agent name, move the card with `status`, and **append** to the
progress log rather than rewriting history: `GET /api/kanban/cards/:id`, edit
the markdown, then `PATCH {"body": ...}` with the whole new body. Timestamps
are Asia/Manila (`date '+%Y-%m-%d %H:%M %z'`). Keep secrets out of the body.

    ## Goal
    One or two sentences: the outcome that means this card is done.

    ## Context
    Why this matters, constraints, related cards (#12), decisions already made.

    ## Agent
    - Host: macmini (or the machine the work runs on)
    - Provider / model: <provider> / <model>
    - Agent id: <agent or session id>
    - Worktree: /path/to/worktree
    - Branch: feature/xyz (commit abc1234, not pushed)

    ## Status / progress log
    - 2026-10-16 19:45 +0800: picked up; reading the existing code
    - 2026-10-16 20:10 +0800: migration written, tests green
    - 2026-10-16 20:30 +0800: **blocked**: needs Kix to approve the DNS change

    ## Findings
    - What you learned that is not obvious from the code (gotchas, numbers, error messages).

    ## Next steps
    - [x] done step
    - [ ] the next concrete step, small enough to start immediately
    - [ ] verification to run before moving to Done

    ## Links
    - PR / commit: https://…
    - Logs, docs, dashboards: https://…

Checklist items (`- [ ]` / `- [x]`) show as a `☑ done/total` badge on the
board card and can be ticked in the card modal (which PATCHes the body). The
board shows `body_preview`, the first prose line (headings skipped), so make
the first line under `## Goal` a good one-line summary.

### Native macOS telemetry

`GET /api/stats` returns live CPU utilization, average CPU-die temperature,
unified-memory use, and system power. Native Apple SMC/IOReport counters are
read by macmon; psutil reads macOS CPU/memory counters. System power is the
SMC device estimate, not an external wall-plug measurement. `GET
/api/stats/history?seconds=3600` returns the one-hour series. Collection runs
once per second even with the browser closed. Stale sampler output returns 503.

### Filesystem explorer — host FS, rooted at ~

The Files tab (`/#/files`) browses the host filesystem, opening at `~`. Paths are
lexically normalised (no shell interpolation); empty/missing `path` means `~`.
The API below backs the tab and works from curl. There is no chroot — like the
shell, it runs as the dashboard user.

| Method | Path | Behavior |
|--------|------|----------|
| GET    | /api/fs/list?path=… | Folder listing. Returns `{path, name, parent, home, places, entries, total, truncated}`; `entries` is capped at 2,000 and `truncated` is true when the folder held more, so `total` counts the entries returned. Each entry: `{name, path, type (dir/file/link/other), is_dir, is_link, size, mtime, mode, hidden, readable, writable}`. 404/400/403 on missing/not-a-dir/denied. |
| GET    | /api/fs/stat?path=… | One entry plus `mime`, `owner`, `group`, `uid`, `gid`, `link_target`, and ISO times (`mtime_iso`, `ctime_iso`, `btime_iso` on macOS). |
| GET    | /api/fs/read?path=… | Read one UTF-8 text file for the inline editor. Returns `{path, name, text, size, mtime}`. 404 missing; 400 directory or not a regular file; 403 denied; 413 over 2 MB; 415 binary (NUL byte or non-UTF-8). |
| GET    | /api/fs/download?path=… | Stream one file as an attachment (range-capable). 400 for directories. |
| PUT    | /api/fs/write | JSON `{path, content}` — overwrite one existing text file, in place, UTF-8, permissions kept. 404 missing; 400 directory/not-regular/missing content; 403 not writable. |
| POST   | /api/fs/upload | Multipart form: `path` (target folder), one or more `file`, optional `overwrite=1`. 409 when a name exists and overwrite is off. |
| POST   | /api/fs/mkdir | JSON `{path}` or `{parent, name}` — create one folder. |
| POST   | /api/fs/touch | JSON `{path}` or `{parent, name}` — create one empty file. |
| POST   | /api/fs/rename | JSON `{path, name}` — rename within the same folder. |
| DELETE | /api/fs?path=… | Delete a file, symlink, or folder (recursive). Refuses `~`, `/`, and ancestors of `~`. |

`name` values are reduced to a single path component (basename), so separators and
`..` cannot escape the target folder. Symlinks are operated on directly — deleting
a link removes only the link, never its target.

### Web shell — interactive host tty rooted in ~

The Shell tab (`/#/shell`) is a live WebSocket terminal. Each browser owns a
tmux session on the host, started with cwd `~` (`/Users/kixpanganiban`). The HTTP API below provides the same session operations; agents generally don't need it, but it works from curl too.

| Method | Path | Behavior |
|--------|------|----------|
| POST | /api/shell/new | Create (or attach to) a session. JSON `{"id"?, "cols"?, "rows"?}` → `{"id", "session", "cols", "rows", "cwd": "~"}`. Omit `id` for a server-generated one. |
| GET  | /api/shell/pane?id=… | Snapshot: `{"alive", "text" (ANSI, visible pane), "cursor_x", "cursor_y", "cols", "rows", "cmd"}`. 404 when the session is gone. |
| POST | /api/shell/input | Type literal text. JSON `{"id", "text"}` (max 4096 chars, stdin-piped — no shell quoting). |
| POST | /api/shell/key | One special key. JSON `{"id", "key"}` where key is a named key (Enter, Backspace, Tab, Escape, Up/Down/Left/Right, Home, End, PageUp, PageDown, Delete, Insert) optionally prefixed with `C-`/`M-`/`S-` (e.g. `C-c`, `M-Left`, `C-M-x`, `S-Tab`), or one printable character. |
| POST | /api/shell/resize | JSON `{"id", "cols", "rows"}` (clamped 20–300 × 5–100). |
| POST | /api/shell/kill | Destroy the session. JSON `{"id"}`. |
| GET  | /api/shell/list | Dashboard-owned host sessions (`dash-*`). |

Session ids match `^[A-Za-z0-9_-]{1,32}$`; tmux names are `dash-<id>`.
Persistence lives in host tmux, so the API is stateless across gunicorn workers.

### Shell over websocket (live tab transport)

The Shell tab itself doesn't poll — it holds one websocket per tab and the
server pushes snapshots (plus an immediate push after every input):

    ws://<host>:5556/ws/shell?id=<sid>   (service `shell-ws`, stdlib only)

Client → server (JSON text frames):

| Message | Behavior |
|---------|----------|
| `{"t":"input","text":…}` | Type literal text (max 4096 chars, same as HTTP) |
| `{"t":"key","key":…}` | One allowlisted special key (same set as HTTP) |
| `{"t":"resize","cols":…,"rows":…}` | Resize the pty |
| `{"t":"new"}` | Kill + recreate the session (keeps pty size) |

Server → client:

| Message | Behavior |
|---------|----------|
| `{"t":"hello","id":…,"cols":…,"rows":…,"cwd":"~"}` | Sent on connect (session created if missing) |
| `{"t":"pane","alive":true,"text":…,"cursor_x":…,"cursor_y":…,"cols":…,"rows":…,"cmd":…}` | Snapshot, sent only when it changes (idle = silent) |
| `{"t":"pane","alive":false,…}` | Session is gone (client shows "press New") |
| `{"t":"error","error":…}` | Bad message content (connection stays open) |

## Agent etiquette

- Daily Brief content is markdown. Preserve existing structure when appending — don't rewrite an entry unless the user asks.
- The Daily Brief is meant for Kix: one markdown entry per calendar day. If asked to "post the daily brief," write today's entry in Manila time.
- The UI at / is read-only from an agent's perspective; do all writes through the API.
- Kanban: use your agent name as `owner` so cards are attributable; move cards rather than deleting them when work finishes (Done is a lane). Don't delete or rename lanes unless asked, and only call archive-done when asked (it sweeps everyone's Done cards); archive a single card with PATCH instead.
- No auth headers needed. Keep requests on the LAN/tailnet.
