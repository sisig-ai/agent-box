# Macmini Control Surface

Base URL: http://macmini:5555 (also http://100.114.80.24:5555 over the tailnet)

**MCP endpoint: `POST http://macmini:5555/mcp`** — use this for the Ops Board
(kanban), the Daily Sitrep / weekly schedule, and the Progress Bars. The HTTP API
documented at the bottom still exists for scripts, but new work should use MCP.

Local home-server landing page + agent surface for Kix's "quick-arr-stack".
No authentication. Exposed only over the LAN / tailnet — treat it as private.

## Host context

- Machine: macmini (Apple M2 Pro, 32 GB unified memory, macOS)
- Timezone: Asia/Manila (UTC+8). All dates are YYYY-MM-DD in Manila time; omitting a date defaults to today (Manila).
- Services on the landing page: Coins.ph Agent (:7777), Hermes Agent (:9119), Opencode (:4096).

## MCP server (primary interface)

Transport: **Streamable HTTP, stateless**. One JSON-RPC 2.0 message per POST
(batches are also accepted). No session id and no server-initiated stream, so
`GET /mcp` and `DELETE /mcp` answer 405 — that is expected, not a fault.
Protocol version `2025-06-18` (also accepts `2025-03-26` and `2024-11-05`).

Register it once:

    # Claude Code / Claude Desktop
    claude mcp add --transport http macmini http://100.114.80.24:5555/mcp

    # Cursor / any client that takes mcp.json
    {"mcpServers": {"macmini": {"url": "http://100.114.80.24:5555/mcp"}}}

Smoke test with curl (handshake, then call):

    curl -s -X POST http://macmini:5555/mcp -H 'Content-Type: application/json' \
      -d '{"jsonrpc":"2.0","id":1,"method":"initialize",
           "params":{"protocolVersion":"2025-06-18","capabilities":{},
                     "clientInfo":{"name":"curl","version":"0"}}}'

    curl -s -X POST http://macmini:5555/mcp -H 'Content-Type: application/json' \
      -d '{"jsonrpc":"2.0","method":"notifications/initialized"}'

    curl -s -X POST http://macmini:5555/mcp -H 'Content-Type: application/json' \
      -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'

    curl -s -X POST http://macmini:5555/mcp -H 'Content-Type: application/json' \
      -d '{"jsonrpc":"2.0","id":3,"method":"tools/call",
           "params":{"name":"create_card",
                     "arguments":{"title":"Renew the domain","owner":"hermes"}}}'

Every successful call returns `content[0].text` (pretty-printed JSON) and, when
the payload is an object, the same data in `structuredContent`. A failed call
returns `result.isError: true` with a human-readable message, so read the text
instead of assuming success. Protocol problems come back as JSON-RPC errors:
`-32602` unknown tool or bad params, `-32601` unknown method, `-32700` body was
not JSON (HTTP 400).

### Tool catalogue

**Board (kanban)**

| Tool | What it does |
|------|--------------|
| `board_overview` | Lanes plus cards. Filters: `status`, `owner` (alias `author`), `opname`, `archived` (`exclude`/`include`/`only`), `include_body`. |
| `list_cards` | Cards only, same filters. Bodies are omitted unless `include_body` is true. |
| `list_archived` | Archived cards, most recently archived first. |
| `get_card` | One card with its full markdown `body` and its `comments` thread. |
| `search_cards` | `q` (required) + optional `status`, `owner` (alias `author`), `opname`, `archived`, `limit` (default 50, max 200). Full-text (FTS5) over titles, bodies, comments, opnames and owners: words are ANDed and match prefixes, `"a phrase"` is exact, `-word` excludes. Results are best-match first; each has `matched` (`title`/`body`/`comment`/`meta`) and a `snippet` whose hits are wrapped in `\x01…\x02`. Search before creating a card that may already exist. |
| `list_opnames` | Existing operation names with card counts — reuse a spelling instead of inventing one. |
| `create_card` | `title` (required), `owner`, `status` (lane, default first lane), `position`, `body`, `opname`. |
| `update_card` | `id` (required) plus any of `title`, `owner`, `body`, `opname`, `status`, `position`, `archived`. |
| `delete_card` | Delete a card and its comments. Prefer moving finished work to Done. |
| `archive_done` | Archive every live card in Done. Sweeps everyone's cards — only when asked. |

**Card comments** — `list_comments(card_id)`, `add_comment(card_id, author, body)`,
`delete_comment(card_id, comment_id)`. Comments are the easy way to log progress
without rewriting a body; `add_comment` bumps the card's `updated_at`.

**Lanes (columns)** — `list_lanes`, `create_lane(name, position?)`,
`update_lane(lane, name?, position?)`, `delete_lane(lane, target?, force?)`.
A lane is referenced by name (case-insensitive) or numeric id. Deleting a lane
with cards needs `target` (move them) or `force` (delete them). Don't rename or
delete lanes unless asked.

**Daily Sitrep (one markdown entry per day)**

| Tool | What it does |
|------|--------------|
| `get_sitrep(date?)` | That day's markdown; empty `content` when no entry exists. |
| `list_sitreps(limit?)` | Recent days, newest first (default 30, max 365). |
| `put_sitrep(content, date?)` | Create or replace a day's entry. |
| `delete_sitrep(date?)` | Remove a day's entry. |

**Weekly schedule (keyed by that week's Monday)**

| Tool | What it does |
|------|--------------|
| `get_schedule(week?)` | The week's markdown; any date in the week is accepted and coerced to the Monday. |
| `list_schedules(limit?)` | Recent weeks, newest first (default 20, max 104). |
| `put_schedule(content, week?)` | Create or replace that week's entry. |
| `delete_schedule(week?)` | Remove that week's entry. |

**Progress Bars (shared visual tracking for humans and agents)**

A bar is a title, a `percent` (0–100, fractions allowed), optional `owner`, and
any number of flat `fields` shown as k-v pairs on the card. Bars nest through
`parent_id`; children render under their parent (a batch's completion bar can
have a budget child). Everyone shares one set — no per-agent namespaces.

| Tool | What it does |
|------|--------------|
| `list_progress_bars(flat?, archived?)` | Roots with nested `children` (default), or every bar in one list with `flat=true`. `archived` is `exclude` (default), `include`, or `only`. `count` is the returned bars; `archived_count` is the total archived. |
| `get_progress_bar(id)` | One bar with its nested children and fields (archived included). |
| `create_progress_bar(title, percent?, parent_id?, fields?, owner?, position?)` | Create a bar. `parent_id` nests it; `position` orders siblings. Archived bars cannot take new children. |
| `update_progress_bar(id, …)` | Change `title`, `percent`, `owner`, `parent_id`, `position`; `fields` replaces the map, `add_fields` merges, `remove_fields` deletes keys. Set `archived=true` to hide this bar and its nested bars, `false` to restore them. Call this as work progresses. |
| `delete_progress_bar(id, cascade?)` | Delete a bar. Refused with a child count when it has children unless `cascade=true`. Archiving is the reversible alternative. |

Use `fields` for the numbers that matter and keep them updated alongside
`percent` (e.g. `{"done": 374, "total": 1000, "cost": "$18.00"}`). Percentages
are independent: a parent does not auto-compute from its children.


**Docs (prefix-keyed text store for long-horizon work)**

A doc is one object: a slash-separated `prefix` that acts as the key (for
example `handoffs/2026-11-02-box-assistant.md`), arbitrary text `content`,
a free-text `author`, `tags`, and created/updated timestamps plus a `revision`
that increments on every write. Prefixes have no leading or trailing slash and
no `.` or `..` segments. Full-text search covers prefix, content, tags and
author.

| Tool | What it does |
|------|--------------|
| `put_doc(prefix, content, author?, tags?)` | Create or replace the doc at that prefix. Replacing overwrites content, author and tags in full and bumps `revision`. |
| `get_doc(prefix)` | One doc in full. |
| `patch_doc(prefix, content?, author?, tags?)` | Update only the fields you pass; keeps the rest. |
| `list_docs(prefix?, limit?, offset?)` | Metadata only (no content), newest update first; `prefix` narrows to a path and its descendants. |
| `search_docs(q?, prefix?, prefix_q?, limit?)` | 15 rows unless `limit` says otherwise. Full-text search; terms are prefix-matched, `-word` excludes, `"two words"` is a phrase. `prefix` scopes to a path and its descendants; `prefix_q` matches any part of the key (`card-389`, `handoffs/`). With `q` empty and `prefix_q` set it is a prefix listing, newest first. Hits carry a snippet with `\\u0001`/`\\u0002` around the match. |
| `semantic_search_docs(q, prefix?, prefix_q?, limit?)` | 15 rows unless `limit` says otherwise. Meaning-based search: embeds the query with the local Ollama model and ranks stored chunk vectors by cosine. A hit does not need to share words with the query. `prefix_q` narrows to a substring of the key (a vector search always needs `q`). |
| `reindex_docs()` | Queue every doc whose vectors are stale, missing or from another model. Indexing already happens on each write; this is for backfill. |
| `delete_doc(prefix)` | Remove one doc. Irreversible; only when asked. |

Semantic search runs fully offline: Ollama on this host (`DASH_OLLAMA_URL`,
default `http://127.0.0.1:11434`) with `DASH_EMBED_MODEL` (default
`nomic-embed-text`, 768-d). Vectors are chunked at ~1200 characters and stored
as float32 blobs in the `doc_embedding` table; a query scores them in Python, so
there is no separate vector service to run. Indexing happens on a background
thread after each write, so a write never waits on the model. Prefer
`search_docs` for exact identifiers and `semantic_search_docs` for "where did I
write about ..." questions; the UI shows exact hits first and appends semantic
ones below them.

Read before you rewrite: `put_doc` is a full replace, so a stale copy silently
drops whatever changed in between. Use `patch_doc` for appends and small edits,
and one prefix per topic so handoffs, specs and research stay addressable.

**Ops Board semantic search**

Cards carry vectors too: title, body, opname and owner are chunked and embedded
by the same local model, so a card can be found by meaning rather than words.
Comments stay in the FTS index only. Indexing runs per card write; use
`reindex_cards` after a model change or to backfill.

| Tool | What it does |
|------|--------------|
| `semantic_search_cards(q, status?, owner?, opname?, archived?, limit?)` | Cosine-ranked cards, best chunk per card, 15 by default. Filters behave like `search_cards`. |
| `reindex_cards()` | Queue every card whose vectors are stale, missing or from another model. |

**Access logs (what agents actually did here)**

Every `tools/call` is recorded: timestamp, tool, the entity it touched (doc
prefix, card id, lane id, bar id, sitrep date, schedule week), whether it
succeeded, how long it took, and a trimmed argument summary.

The log rotates daily: one JSON-lines file per day under `data/logs/`
(`access-YYYY-MM-DD.log`), and anything older than 7 days is deleted from both
the files and the `mcp_access_log` table on the next write or read. The table
also keeps a 20,000-row hard cap as a burst guard, so it is a recent-activity
view, not an archive.

| Tool | What it does |
|------|--------------|
| `list_access_logs(limit?, tool?, entity?, ok?)` | Recent invocations, newest first. `tool` narrows to one name, `entity` is a substring match, `ok=false` shows only failures. |

### Conventions

- Dates are Manila time. Omit them for "today"/"this week" rather than guessing a UTC date.
- Set `owner` (cards) and `author` (comments) to your agent name so work is attributable.
- Keep a card's body in the handoff shape: `## Goal` (one-line outcome), `## Context`, `## Agent` (host, provider/model, worktree/branch), `## Status / progress log` (append timestamped lines), `## Findings`, `## Next steps` (`- [ ]` items), `## Links`.
- Read the card before replacing its body (`get_card`), then append — never rewrite history, and keep items Kix already ticked as `- [x]`.
- Sitrep items Kix should act on go in as `- [ ] ` task lines on their own line; his ticks persist as `- [x]`, so don't reset them when updating an entry.
- Move finished cards to Done; archive a single card instead of deleting it, and only call `archive_done` when asked.
- Group related cards with `opname` (max 100 chars, e.g. `Operation Valhalla`) instead of inventing a parallel board.
- Track long-running batches and jobs as Progress Bars instead of burying status in a card comment; nest a budget or per-stage bar under the main one and keep `percent` + fields current.
- Timestamps: `date '+%Y-%m-%d %H:%M %z'` on the host. Keep secrets out of bodies and comments.

## Other endpoints on this host (not covered by MCP)

- `GET /api/stats`, `GET /api/stats/history?seconds=3600` — live CPU / temperature / memory / power, sampled once per second.
- `GET /api/procs?sort=rss|cpu|pid|name&order=desc|asc&limit=40` — host processes with `rss_bytes`, `cpu_percent` (one 0.12s sample), `user`, `status`, `cmdline`, and `protected` (init or the dashboard's own ancestry). `POST /api/procs/:pid/signal` with `{"signal":"TERM"|"KILL"}` sends a signal; other users' processes return 403.
- Files (host FS rooted at `~`): `GET /api/fs/list|stat|read|download`, `PUT /api/fs/write`, `POST /api/fs/upload|mkdir|touch|rename`, `DELETE /api/fs?path=…`.
- Shell (tmux-backed tty in `~`): `POST /api/shell/new|input|key|resize|kill`, `GET /api/shell/pane|list`, and the live websocket at `ws://macmini:5556/ws/shell?id=<sid>`.
- Docs REST: `GET /api/docs?prefix=&limit=&offset=&content=1`, `GET|PUT|PATCH|DELETE /api/docs/<path:prefix>`, `POST /api/docs` (body carries `prefix`, 409 if taken), `GET /api/docs/search?q=&prefix=&prefix_q=`, `GET /api/docs/semantic?q=&prefix=&prefix_q=&limit=`, `GET /api/docs/index`, `POST /api/docs/reindex`, `GET /api/docs/prefixes`, `GET /api/docs/tree?per=5`.
- Ops Board semantic: `GET /api/opsboard/semantic?q=&limit=&status=&owner=&opname=&archived=`, `POST /api/opsboard/reindex`.
- MCP access log: `GET /api/logs?limit=&tool=&entity=&ok=1|0` — every `tools/call`, newest first, plus `retention_days` and the retained daily files; `POST /api/logs/rotate` forces a new day file and sweeps the window. Files live in `data/logs/access-YYYY-MM-DD.log`, one JSON object per line, 7-day retention.
- Page tabs: `#/brief` (Daily Sitrep), `#/` (Stack), `#/files`, `#/shell`, `#/kanban` (Ops Board), `#/progress` (Progress Bars), `#/docs` (Docs), `#/logs` (Access Logs).

## Raw REST API (legacy — same data as the MCP tools)

Kept for existing scripts and routines. Prefer the MCP tools; these routes may
change independently of them. No auth headers are needed on any of them.

**Daily Sitrep** — `GET|PUT|POST|DELETE /api/sitrep` (`?date=YYYY-MM-DD`), `GET /api/sitrep/list?limit=N`.
**Deprecated aliases:** `/api/brief` and `/api/brief/list` still work with identical payloads.

**Weekly schedule** — `GET|PUT|POST|DELETE /api/schedule` (`?week=YYYY-MM-DD`), `GET /api/schedule/list?limit=N`.

**Progress Bars** — canonical prefix `/api/progress`; percentages are 0–100, `fields` is a flat JSON object.

| Method | Path |
|--------|------|
| GET | `/api/progress` (roots with nested children), `/api/progress/flat` |
| GET/DELETE | `/api/progress/:id` (`DELETE …?cascade=1` removes the subtree) |
| POST | `/api/progress` |
| PATCH | `/api/progress/:id` |

Listings take `?archived=exclude|include|only` (default `exclude`) and return
`count` plus `archived_count`. POST/PATCH accept `title`, `percent`,
`parent_id`, `fields`, `owner`, `position`; PATCH also accepts `add_fields`,
`remove_fields`, and `archived` (boolean, cascades through the subtree).

**Ops Board** — canonical prefix `/api/opsboard`; `opname` filters every listing.

| Method | Path |
|--------|------|
| GET | `/api/opsboard?status=&owner=&opname=&include_archived=&include_body=` |
| GET | `/api/opsboard/cards`, `/api/opsboard/archived` |
| GET | `/api/opsboard/search?q=&limit=&archived=&status=&owner=&opname=` |
| GET | `/api/opsboard/opnames` |
| POST | `/api/opsboard/cards`, `/api/opsboard/archive-done` |
| GET/PATCH/DELETE | `/api/opsboard/cards/:id` |
| GET/POST | `/api/opsboard/cards/:id/comments` |
| DELETE | `/api/opsboard/cards/:id/comments/:commentId` |
| GET/POST | `/api/opsboard/lanes` |
| PATCH/DELETE | `/api/opsboard/lanes/:lane` |

**Deprecated aliases:** `/api/kanban` and every `/api/kanban/...` subpath call
the same handlers with the same payloads. Swap the prefix for `/api/opsboard` in
new code. Cards carry `opname`, `body`, `has_body`, `body_preview`,
`body_tasks`, `comment_count`; pass `?include_body=1` for full bodies in
listings. Storage: SQLite at
`/Users/kixpanganiban/quick-arr-stack/arr-dashboard/data/briefs.db` (host mount,
survives rebuilds).
